# 2026-09-21 工作日志

## 统信1070 三问题整改（编译报错 / glmark2 缺包 / 安装后 GLIBC 报错）

- 根因：
  1. `/usr/bin/qmake` 是 qtchooser 链接指向 Qt4（二进制缺失），脚本候选列表不校验 Qt 大版本，误选 Qt4；
  2. UOS/麒麟官方源不含 glmark2，`apt-get download` 在编译机（=统信）必然失败；
  3. 包内 lib/ 从编译机复制，编译机 glibc ≥2.30 > 统信1070 的 2.28 → `GLIBC_2.29/2.30 not found`，glibc 无法随包降级，自愈链无效。
- 修复（铁律：统信1070/麒麟V10 的包必须在 glibc ≤2.28 的系统上编译打包）：
  - build/package_deb 的 find_real_qmake 强制校验 QT_VERSION 为 5.*（glob 覆盖全架构）；
  - package_deb/package(tar) 新增 GLIBC 门禁：objdump/readelf 扫全 ELF 最大符号版本，超 `MIN_TARGET_GLIBC`(默认2.28) 即中止；`ALLOW_INCOMPATIBLE_GLIBC=1` 可强放；
  - deb 启动脚本/postinst/tar 启动脚本加 GLIBC 预检中文诊断；
  - glmark2 改可选增强口径 + offline_debs/ 离线 deb 兜底 + 移出 control Recommends；
  - regression_test_elsky.sh 新增 2.5 GLIBC 兼容性检测节。
- 产出报告：`整改报告_统信1070三问题_GLIBC兼容与离线打包_V2.1.md`（含根因/优缺点/注意事项/优化清单/各架构各系统回顾测试矩阵）。
- 待办：真机回归（统信1070 ARM64+AMD64、麒麟V10 SP1、麒麟2503、Ubuntu20/22、Debian10/11）——脚本已全部 bash -n 通过，GLIBC 版本比较逻辑已单测。
